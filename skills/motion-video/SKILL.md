# Text motion

Read [the execution contract](../sadeq-studio/references/execution.md) first to resolve the existing runtime/project and preserve independent works. Read the relevant source context before proposing edits. Read styles.md/capabilities.json. For text-motion requests choose the supported phrase preset and relative intervals through arabic-product-video/timeline-edit. A pop text preset is not a camera zoom; paper is a card treatment, not collage B-roll.

For an explainer, use verified facts and actual project/supplied footage with a coherent outline, short readable text and requested narration. Use voiceover when appropriate. No invented screenshots, interfaces, prices or product behavior. Capturing a real site/app requires actual available browser/tools and authorization for its relevant content; don't render imagined UI as documentary evidence.

The current Studio timeline does not implement standalone 3D scenes, device mockups, free JSX or an automatic generated-image/collage engine. Requested local still images/icons can be imported as independent editable layers with the six shared motion presets. If these are essential to the explicit brief, state the gap and identify the concrete scene assets/integration needed. Don't pass unsupported fields or promise a 60fps 3D film. Deliver a supported footage/text video only when it satisfies the requested scope, otherwise return the clearly labeled preparatory storyboard without claiming final production.
